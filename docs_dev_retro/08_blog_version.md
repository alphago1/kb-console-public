# 我如何用 AI Copilot 搭出一个 Word-first 本地知识库系统

> 两天，4000 行 Python，15 个 bug，199 个重复文件。一次真实的 Vibe Coding 复盘。

---

## 这个项目是干嘛的

我有一个习惯：在桌面随手建 `.docx` 文件记录各种想法——交易复盘、AI 研究笔记、项目思路、日常随笔。两年积累了 200 个 Word 文件。

问题是：我经常记得"写过关于止损的某篇东西"但找不到文件。Windows 搜索太慢，文件名很多时候是第一句话的产物（比如 `0106反思.docx`），完全不可检索。

我的需求很简单：
1. 自动把桌面 Word 文件归类
2. 能搜到"某个想法在哪个文件里"
3. 能一次性读完我关于某个主题写的所有东西，给我一个总结

我决定用 AI Copilot（Claude Code）搭一个。

---

## 第一天：从 CLI 到能用的 GUI

### 起点：一个已经能跑的 CLI 原型

这个项目在找 Copilot 帮忙之前，其实已经有一个 CLI 原型了——32 个命令，SQLite + FTS5 全文检索，DeepSeek 自动分类。不是从零开始。

但 CLI 的问题是：我自己都不想用。每周整理要敲 `python main.py weekly-organize --config config.yaml --max-files 200`，搜文件要敲 `python main.py find --config config.yaml --query "止损"`。这不符合日常使用习惯。

### 第一次尝试：写 Streamlit GUI

我让 Copilot 直接在已有的 CLI 上面盖一个 Streamlit GUI。第一版 9 个平铺页面，功能都在，但界面很差：

- 所有操作卡住 UI（同步等待 CLI 子进程）
- 一个叫"交易分析"的页面把分析功能绑死在 4 个交易分类上
- 设置页面是只读的
- 搜索只有关键词匹配，查不到"不等回调"这种自然语言

用户（我自己）用了一次后给了详细反馈。Copilot 根据反馈写了 v2 计划——6 组导航、异步任务、自定义分析取代硬编码的"交易分析"、设置可读写。

### v2 重写：一次 prompt 出 750 行

我把 mockup 和需求清单给 Copilot，它一次生成 ~750 行 `streamlit_app.py` 和 ~580 行 `ui_helpers.py`。骨架是对的——6 组导航、异步任务框架、配置管理。然后就是长达两天的 bug 修复。

---

## 第二天：15 个 bug 的地狱

v2 上线后，真正的问题才开始暴露。

### Bug 1：GUI 搜索永远返回 0 结果

这是整个过程最让我崩溃的 bug。Copilot 的所有测试都通过了——`find_idea('ai')` 返回 14 条。但我在 GUI 里搜索任何关键词都是 0 条。

排查了一个小时——检查 FTS5 表、检查 chunk 索引、检查 `find_idea` 函数逻辑——全是正常的。

最后发现的问题是：Copilot 从 `kb_tool/` 目录跑所有测试，`config.yaml` 里 `sqlite_path: "./kb_out/kb.sqlite3"` 在 cwd=kb_tool/ 下解析到正确的库（201 条文档）。但 Streamlit GUI 从项目根启动，同一个相对路径解析到了 `root/kb_out/kb.sqlite3`——一个 0 条文档的空库。**同一个代码，不同工作目录，读到了不同的数据库。** Copilot 所有的"测试通过"都是假阳性。

### Bug 2：199 个重复文件

我偶然发现 `docs/` 目录里有文件叫 `Gemini的一些问题_b8eb29c9.docx` 和 `Gemini的一些问题_b8eb29c9_2.docx`。顺藤摸瓜发现这不是个别现象——5 轮清理总共删除了 199 个重复文件，DB 从 400 条记录缩水到 153 条。

追溯根因时发现了三道崩溃的防线：
1. mtime 浮点精度：`os.stat().st_mtime` 是 `1746123456.789123`，存入 SQLite REAL 再读出变成 `1746123456.78912`，`==` 比较失败 → 去重失效
2. `_unique_path` 机械加 `_2` 后缀：发现同名文件就加后缀，不检查内容是否相同
3. **SHA 来自随机采样**（核心设计缺陷）：`fingerprint_sha256 = sha256(sampled_text)`，其中 `sampled_text` 包含 3 段随机位置 500 字的采样。同一文件处理两次 → 采样不同 → 文件名中的 SHA 不同 → 去重彻底失效

第三条是整个项目最大的设计失误——它在原型阶段写的，当时没人意识到这个 SHA 后来会被用作文件名的唯一 ID。原型时期的 hack 变成了系统级 bug。

### Bug 3：子进程"假死"

GUI 点"正式整理"后一直显示"子进程启动中..."，1 分钟没变化。用户以为死机。

原因是 Python 在管道模式下 stdout 4KB 全缓冲。`print()` 不会立即输出到管道 → `readline()` 阻塞 → GUI 永远看不到第一行输出。修复只需要两行：`python -u` + `PYTHONUNBUFFERED=1`，但找到根因花了不少时间。

### Bug 4：LLM 在没数据时编造答案

主题分析选"AI与工具化"文件夹 + topic "我研究了哪些AI技术"。结果是 LLM 的一段话说"根据您的要求，我假设您已研究过……"——因为它根本没读到任何文件。

根因是 `trading_analyze` 写死了只搜 4 个交易分类，完全忽略用户选的"AI与工具化"文件夹。加上 `blocks` 为空时照常调 LLM API——空 prompt + LLM = 高质量幻觉。

### 其他 bug 速览

- Streamlit 的 `st.script_run_ctx` 不存在于当前版本 → AttributeError
- AI 写的代码缺 `import json` → NameError
- 异步任务切页面后进度条消失 → task_id 没存 session_state
- 文件夹分析路径基准用成了项目根而非 docs/ → 找不到任何文件
- 80 篇硬上限 → 改成 100 万字预算制 + 超出自动分批并发压缩

## 什么功能最终留下来了

### Word-first 入库

不改用户的习惯。桌面随手建 Word → weekly_organize 扫描 → AI 分类 → 按 11 个分类归入 `docs/`。用户唯一需要做的就是每周点一次按钮。

### 全文检索（Find）

双模式：快速搜索（SQLite FTS5，毫秒级）+ 智能搜索（Agent 多轮调用知识库工具，10-30 秒）。前者适合"记得某个关键词"，后者适合"想问一个自然语言问题"。

### 自定义分析（Custom Analysis）

不硬编码"交易分析"。用户选择文件夹范围 + 时间范围 + 分析主题 → LLM 读完所有文档 → 输出结构化报告。超出 100 万字自动分批 → 每批 LLM 并发压缩 → 合成。

### 后台任务体系

所有长时间操作（每周整理、主题分析、个人画像）都是后台线程执行。用户可以切换到其他页面，任务不中断。侧边栏实时显示进度。完成时 toast + 提示音。

## Copilot 到底靠不靠谱

### 真的有用的地方

1. **大规模代码生成**：一次出 750 行 Streamlit 代码。前提是你已经验证了设计方向（有 mockup）。
2. **根因追溯**：从 `_2` 后缀 → `_unique_path` → `weekly_organize` → `database.process_file` → `sampler`。5 层追溯，30 秒完成。人也能做，但 Copilot 顺着调用链跳转快得多。
3. **同类问题扫描**：`grep` 11 个函数，列出哪些调了 init 哪些没调。5 秒。
4. **测试生成**：39 个后端函数测试 + 33 个 CLI 测试，一次生成基本可用。
5. **文档结构化**：从"写一套复盘文档"自动展开为 10+2 个文件的完整体系。

### 真的不靠谱的地方

1. **"已完成"三个字绝对不可信**。Copilot 的判断标准是"我改了代码"，用户的判断标准是"改了之后能用"。每次它说"完成"都必须要求贴验证命令。
2. **测试环境 ≠ 运行环境**。Copilot 在自己方便的工作目录下测试，不会主动质疑"我的测试方式和用户使用方式一样吗"。这是最危险的假阳性。
3. **不预警设计隐患**。它看到 `sampled_text` + `sha256` 的组合从没主动说"这可能有问题"。
4. **方案偏复杂**。优先推荐引入新技术栈（Embedding / ChromaDB），而不是复用现有的（Agent + MCP）。需要人问一句"有没有更简单的做法"。
5. **代码细节错误**。缺 import、用错 API 名、typo。每次生成后必须跑语法检查。
6. **默认串行不并发**。for 循环调 LLM API——人需要主动指出"这些操作互不依赖，并发"。

### 最佳协作模式

```
人：明确需求 + mockup + 审查方案方向
  ↓
Copilot：生成代码 + 写测试 + 追溯根因 + 扫描同类
  ↓
人：从用户路径验证 + 语法检查 + 全量测试
  ↓
Copilot：根据验证结果修复
  ↓
人：再验证 → 接受
```

Copilot 像一个"非常快但不会质疑你的初级工程师"——它负责广度（写出所有代码），人负责深度（判断方向 + 真实验证）。

## 如果你也想用 Copilot 搭个人工具

1. **先做 mockup**。用假数据搭一个能点击的原型给用户看。这个 1 小时的投资能省掉后面一整天的返工。
2. **第一条规则：路径绝对化**。`config.yaml` 中每一个路径在加载时立即 `Path.resolve()`。不要相信工作目录。
3. **内容指纹用全文 SHA256**。采样文本是不确定的——不能做唯一 ID。
4. **子进程加 `-u`**。否则你会在"子进程启动中"等一分钟。
5. **LLM 调之前检查输入**。空数据 + LLM = 高质量幻觉。blocks 为空就别调 API。
6. **Copilot 说"完成" = 没完成**。自己跑一遍用户的操作路径。
7. **git commit 要勤**。每次关键节点前保存。Copilot 改了很多文件后，回退成本很高。
